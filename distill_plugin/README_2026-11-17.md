# 2026-11-17 自定义 YOLOv5 可插拔 FGD 附件

学生使用原模型 YAML，不增加网络层，不改变 ReLU、单通道输入、自定义数据预处理或检测损失。新增的蒸馏实现、教师配置、调度脚本、测试和说明都在 `distill_plugin/`。训练入口及权重读取有少量接入与兼容修改。

## 新服务器直接启动

使用已有的训练 Python 环境，在仓库根目录运行：

```bash
python distill_plugin/start_2026-11-17.py --mode all
```

默认从原工程 `/home/sunyu/project/gesture_asc/gesture_train_shared/epoch76.pt` 读取学生初始权重，数据 YAML 仍指向服务器现有数据。仓库没有包含权重和数据，不需要复制进新仓库。其他位置用 `--weights /absolute/path/epoch76.pt` 和 `--data /absolute/path/data.yaml` 指定。

| 顺序 | 物理 GPU | 训练 | 初始权重 | batch | 输入参数 |
|---|---:|---|---|---:|---|
| 并行阶段 | 0 | 原学生有监督对照 | 原 `epoch76.pt` | 128 | `--imgsz 320` |
| 并行阶段 | 1 | 同系列 M 规模教师 | 默认从头训练；可传 `--teacher-init` | 16 | `--imgsz 320` |
| 前两组成功完成后 | 0 | 原学生 + FGD | 同一份原 `epoch76.pt` | 128 | `--imgsz 320` |

默认每组 200 epochs、save-period 1、seed 0，保持原指令设置。`--student-batch`、`--seed`、`--epochs` 同时作用于对照和 FGD。教师 batch 单独设置，不混入学生对照。batch 128 沿用用户原指令，尚未在这两张真实 GPU 上验证显存；如 OOM，不会自动改 batch 后继续比较，应保留失败记录并以同一较小学生 batch 新跑整对。

脚本后台运行并返回 PID；日志断开不停止队列。每张卡启动前检查 `nvidia-smi`，使用用户级 GPU 锁和队列锁，发现已有计算进程就退出，不终止任何已有进程。首次阶段若一组失败，会保留另一组到结束，并阻止继续蒸馏。训练异常、OOM 不算完成，也不自动覆盖重启。

输出集中到 `runs/北京时间日期_时分秒_fgd_deployment/`：`plan.json`、`status.json`、`queue.log`、各训练日志、`baseline/teacher/fgd`、`summary.json` 和 `report.md`。报告读取实际 best.pt 内保存的验证指标，列 P、R、mAP50、mAP50–95、由平均 P/R 推导的 F1*，以及 FGD 减对照的百分点变化，正负都报告。它不是测试集结果，也未包含端侧速度。

原对照已经在 GPU0 运行时，不要重复 `--mode all`。可以仅用空闲 GPU1 训练教师：

```bash
python distill_plugin/start_2026-11-17.py --mode teacher
```

教师结束且 GPU0 空闲后，单独启动蒸馏（替换真实教师路径）：

```bash
python distill_plugin/start_2026-11-17.py --mode distill \
  --teacher-checkpoint /absolute/path/teacher/weights/best.pt
```

这类单独启动的报告只涵盖该队列里的训练，不会伪造或自动匹配外部对照。`--mode parallel` 只跑前两组，`--mode baseline` 只跑原学生。GPU 被他人占用时请等待，不更改可见卡绕过检查。

## 原指令如何启用或关闭

原学生配置路径和其他参数保持原样，只追加：

```bash
--teacher_weight /absolute/path/teacher/weights/best.pt \
--distill-method fgd --fgd-weight 0.005 --fgd-warmup-epochs 3
```

不传 `--teacher_weight` 就关闭蒸馏，走原来的有监督 ComputeLoss。只传 `--teacher_weight` 而不选 FGD，则保留旧的输出蒸馏分支，其教师输入仍是两倍插值。FGD 不叠加旧输出损失，便于明确归因。

FGD 在 Detect 前的 P3/P4/P5 特征上执行前景、背景、注意力和全局关系损失；独立 1×1 对齐层把学生通道对齐教师。教师冻结并优先读取其 EMA，类别数量、顺序及特征 stride 必须一致。师生吃同一份增强和裁剪后的输入，GT mask 使用与检测损失相同的最终 targets。损失按 batch 缩放后加到原检测损失，适配层加入优化器和梯度裁剪，FP32 计算 FGD，前三轮线性增加到 0.005。

教师仅将原自定义模型的 `depth_multiple/width_multiple` 改为标准 M 的 `0.67/0.75`；其余结构、层连接和 ReLU 不变。17 类下学生 **2,261,478** 参数，教师 **20,932,518** 参数。它是自定义单通道 M 规模教师，不等同于下载官方 RGB YOLOv5m 权重直接使用。

`--imgsz 320` 保留项目原有含义，不能写成 320×320 RGB：真实 loader 在本地短训练中生成 **1×224×320** 张量，其他实际数据/预处理分支应以运行记录为准。该分支原有的尺寸和 targets 修正都未改。数据 YAML 有 17 类，原模型 YAML 的 nc=11 会由原训练入口按数据覆盖为 17。hyp 文件名虽然含 focaler，但当前实际 loss.py 已删除该项，保留的 MPDIoU/NWD/BCE 等逻辑完整保留；没有补回文件名中的算法。

## 部署与恢复

`best.pt` 是标准学生检查点，不带教师或 FGD 对齐层，也没有残留 hook；蒸馏不增加部署模型参数和网络算子。`fgd/weights/last.pt` 保留 FGD 对齐层、优化器和 AMP scaler 状态，供中断恢复；正常训练结束不剥离它。部署和验证使用 `best.pt`。

```bash
CUDA_VISIBLE_DEVICES=0 python train.py --resume /absolute/path/fgd/weights/last.pt
```

恢复会核验教师权重 SHA256 和 FGD 配置，不接受缺失对齐层状态或更换了教师的断点。恢复流程已做实际短训练检查；自定义 loader 的采样随机流没有完整持久化，因此不承诺与不中断训练逐位一致，确认性配对实验应整对连续运行。

## 验证方法与边界

在仓库根目录运行：

```bash
python -m unittest discover -s distill_plugin/tests -v
python distill_plugin/smoke_2026-11-17.py --output /tmp/gesture_fgd_smoke_unique
```

smoke 使用独立合成图片及真实自定义 loader，完成教师、原学生、FGD 学生各 2 epochs，测试断点恢复、保存和融合后独立推理。测试目录必须尚不存在，保留所有失败记录。合成数据仅验证执行，不能证明精度收益。真实数据精度、CUDA AMP、GPU显存和两卡长训练需在新服务器实际运行后确认；服务器 GPU 延时不能称为端侧延时。

FGD 是既有研究中值得优先迁移的候选：旧的约 1M、224 学生在同一旧测试口径的三个种子变化为 +0.79、+0.98、−0.03 个百分点，平均 +0.58；新结构、新数据不保证复现该收益。先用本次验证集比较，发现提升后再 seed42/43/44 配对复核，并在配置固定后执行预先约定的测试。

## 接入文件范围

附件主体都在本目录。外部接入点只有 `train.py`（可选分支、保存和日志）、`utils/general.py`（单通道 AMP 探测和部署权重剥离）、`models/experimental.py`（新旧 PyTorch 检查点读取）和 `models/common.py`（移除完全未使用、在 torch1.13 上会导入失败的 FlashAttention/SDPA 探测）。Conv、C3、SPPF、Detect 的定义、学生模型 YAML、模型解析器、数据 YAML、自定义 loader 和检测损失均未更改。无需新增训练依赖；使用原项目已可运行的环境。
