| 方法 | 做什么 | 数据与用途 |
|---|---|---|
| PTQ | 用已训练模型和代表性数据校准scale/zero point，再评估量化损失 | 本实现只从训练划分采样，默认1024图，无梯度更新 |
| QAT | 在权重/激活假量化噪声下微调学生权重 | 有标签训练集，默认20轮、SGD学习率1e-5、batch16 |
| 浮点微调对照 | 相同起点、微调轮数、batch、增广和验证流程，关闭假量化 | 区分额外微调收益与QAT收益；不是此前200轮对照的直接替代 |

PTQ不一定都要重新监督训练；AdaRound、CLE、SeqMSE等是进一步的PTQ优化选项，本版先实现基本校准与QAT，尚未接入这些算法。QAT旨在减少量化相对浮点的精度损失，不保证超过浮点模型。

## 4. 正式实验

冒烟通过后，使用同一未蒸馏best.pt作为起点。本轮默认不叠加蒸馏，以便单独衡量量化损失和QAT恢复效果。

```bash
# GPU0：先自动测FP32和PTQ，再QAT微调；不需要重复单独跑PTQ。
python -u qat_plugin/run_2026-11-24.py --mode qat --device 0 \
  --epochs 20 --batch-size 16 --val-batch 16 --lr 0.00001 --seed 0
```

在GPU1也空闲且获授权时，可以在另一个终端并行微调浮点对照：

```bash
python -u qat_plugin/run_2026-11-24.py --mode float-control --device 1 \
  --epochs 20 --batch-size 16 --val-batch 16 --lr 0.00001 --seed 0
```

两张卡型号不同，训练耗时不能作为量化加速结论；若无法容纳相同batch，先停止自己的该次失败运行并把两组都改成同一更小batch再比较，不把不同batch当配对。只希望校准/导出时用`--mode ptq --device 0`。

## 5. 实现细节和输出

| 项目 | 本版行为 |
|---|---|
| 源模型 | 完整加载受信任学生checkpoint，验证数据类顺序和学生YAML，禁止部分加载 |
| 参数解冻 | best.pt通常requires_grad=False，显式解冻；BN折叠产生的新Conv同样解冻 |
| 模型准备 | 对副本折叠Conv+BN，Add/Concat模块化、SPPF三次池化分成独立模块；校准前对齐原模型输出 |
| 量化图 | 量化backbone/neck及全部3个Detect卷积，输出原始P3/P4/P5的5维logits；浮点解码适配原val.py |
| 输入/标签 | 使用原nopad_nopar dataloader、原--imgsz320分支和原Y裁剪标签变换；实际形状从batch记录，非硬编码RGB320方图 |
| 微调 | 关闭Mosaic/MixUp/CopyPaste，其余hyp不改；FP32计算、无AMP/EMA/AutoAnchor、无蒸馏；固定校准范围QAT，不学习激活范围 |
| loss | 保留原ComputeLoss与缩放；除以batch得到平均梯度，因此默认1e-5是本入口学习率，不能与旧train.py数值直接等同 |
| 选择规则 | 只按验证集0.1*mAP50+0.9*mAP50–95；包含微调前起点，若QAT未胜过PTQ则best_epoch=-1并明确标记 |
| 完整记录 | 每轮结果、最佳与末轮状态、校准图片路径、配置/初始化SHA、训练/验证路径列表SHA、各类P/R/F1/AP50/AP50–95/AP95；关闭旧绘图路径 |
| 负结果 | 记录PTQ-FP32、QAT-FP32、QAT-PTQ全部正负百分点；全程历史保留，即使最佳仍是PTQ |

结果位于`gesture_train_shared_QAT/runs/北京时间_aimet_模式/`：`status.json`、`manifest.json`、`summary.json`、`history.json`、各验证目录`metrics.json`、`best_sim_state.pt`、`last_sim_state.pt`。state文件含假量化/优化器，是训练状态，不是压缩后的部署INT8权重；本版不提供断点恢复命令，勿当作原YOLO best.pt加载。

QAT/PTQ导出目录包含`gesture_w8a8.onnx`和`deployment.json`，使用当前AIMET ONNX QDQ接口，量化scale/zero point嵌入图中（无需额外.encodings文件）。权重预量化，解码参数另存。ONNX checker检查和Q/DQ存在性检查会运行；真实目标编译与端侧速度必须后续实测。`--skip-export`仅可用于诊断训练，不视为完成部署。

浮点约2.26M参数，INT8纯权重理论约2.26MB，FP32纯权重约9.05MB；相对已有FP16 best.pt约4.8MB，不能声称文件必然再缩小4倍。参数数量不会因量化减少，实际文件/设备包受偏置、scale、浮点操作和容器开销影响。

目前不自动运行正式测试集、不报告端侧速度。AP95由原验证器10列AP矩阵的IoU0.95端点读取，不能把mAP50–95当AP95；原验证器未计算该矩阵时AP95记录null。发现明确量化收益后，再预注册seed42/43/44同条件复核；芯片明确后调整quant-config并编译验证，不保证通用配置符合特定NPU。
